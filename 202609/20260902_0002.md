

### 8. 서블릿 확장 API 사용하기

#### 서블릿에서 사용하는 포워드방법(4)
```aiignore
서블릿에서 사용하는 포워드방법(4)

1. redirect
HttpServletResponse.sendRedirect("포워드할 URL");
웹브라우져에게 접속 재요청


2. refresh
HttpServletResponse.addHeader("Refresh", ...);
웹브라우져에게 접속 재요청


3. location.href 이용 
자바스크립트 재요청 
location.href="...";


4. dispatch
RequestDispatcher dispatcher = request.getRequestDispatcher("포워드할 URL");
dispatcher.forward(request, response);
서블릿에서 다른 서블릿으로 포워드
클라이언트를 거치지 않고, 바로 다른 서블릿에게 요청한다.
```



```aiignore
https://jakarta.ee/specifications/platform/8/apidocs/javax/servlet/http/httpservletresponse#sendRedirect-java.lang.String-

void sendRedirect(String location)
           throws IOException
Sends a temporary redirect response to the client using the specified redirect location URL and clears the buffer. The buffer will be replaced with the data set by this method. Calling this method sets the status code to SC_FOUND 302 (Found). This method can accept relative URLs;the servlet container must convert the relative URL to an absolute URL before sending the response to the client. If the location is relative without a leading '/' the container interprets it as relative to the current request URI. If the location is relative with a leading '/' the container interprets it as relative to the servlet container root. If the location is relative with two leading '/' the container interprets it as a network-path reference (see RFC 3986: Uniform Resource Identifier (URI): Generic Syntax, section 4.2 "Relative Reference").
If the response has already been committed, this method throws an IllegalStateException. After using this method, the response should be considered to be committed and should not be written to.

Parameters:
location - the redirect location URL
Throws:
IOException - If an input or output exception occurs
IllegalStateException - If the response was committed or if a partial URL is given and cannot be converted into a valid URL


```


```aiignore
네. HttpServletResponse.sendRedirect(String location)의 location에는 절대 URL뿐 아니라 상대 URL도 지정할 수 있습니다.

예를 들어 현재 요청 URL이 다음이라고 가정하겠습니다.

http://localhost:8080/webShop/member/login

컨텍스트 경로는 /webShop입니다.

1. 완전한 절대 URL
response.sendRedirect("https://www.google.com/");

브라우저는 그대로 다음 주소로 이동합니다.

https://www.google.com/

다른 사이트로 보내는 경우에도 사용할 수 있습니다.

2. / 없이 시작하는 상대 URL
response.sendRedirect("main");

API 문서의 이 부분에 해당합니다.

If the location is relative without a leading '/', the container interprets it as relative to the current request URI.

현재 요청이

/webShop/member/login

이라면 현재 요청 URI를 기준으로 해석되어 대략 다음과 같이 이동합니다.

http://localhost:8080/webShop/member/main

예를 들어:

response.sendRedirect("../main");

이라면:

http://localhost:8080/webShop/main

처럼 상대경로 해석이 적용됩니다.

3. /로 시작하는 상대 URL
response.sendRedirect("/webShop/main");

문서에서 말하는:

relative with a leading '/'

경우입니다. 여기서 중요한 점은 /가 현재 Web Application의 Context Root가 아니라 Servlet Container의 Root라는 것입니다.

따라서:

response.sendRedirect("/webShop/main");

→

http://localhost:8080/webShop/main

반면 다음처럼 하면:

response.sendRedirect("/main");

→

http://localhost:8080/main

이 됩니다.

즉 /webShop이 자동으로 붙는 것이 아닙니다.

4. Context Path를 이용하는 실무적인 방법

Web Application의 Context Path가 변경될 가능성을 고려하면 보통 다음처럼 작성하는 것이 좋습니다.

response.sendRedirect(
    request.getContextPath() + "/main"
);

현재 Context Path가 /webShop이라면:

request.getContextPath()

결과는:

/webShop

따라서 최종적으로:

response.sendRedirect("/webShop/main");

과 같은 효과가 됩니다.

이 방법의 장점은 애플리케이션의 Context Path가 바뀌어도 코드를 수정할 필요가 없다는 것입니다.

현재
/webShop
    ↓
/webShop/main

나중에 변경
/shop
    ↓
/shop/main

그래서 Servlet/JSP 애플리케이션에서는 다음 패턴을 많이 사용합니다.

response.sendRedirect(
    request.getContextPath() + "/member/list"
);
정리
코드	기준
sendRedirect("main")	현재 요청 URI 기준
sendRedirect("../main")	현재 요청 URI 기준 상대경로
sendRedirect("/main")	Servlet Container Root 기준
sendRedirect(request.getContextPath() + "/main")	현재 WebApp Context Root 기준
sendRedirect("https://example.com/main")	지정한 절대 URL

따라서 같은 WebApp 내부로 redirect하는 일반적인 경우라면 저는 다음 형태로 이해해 두시는 것을 권합니다.

response.sendRedirect(
    request.getContextPath() + "/main"
);

참고로 sendRedirect()는 서버 내부에서 다른 Servlet으로 바로 이동하는 것이 아니라, 클라이언트에게 302 Found + Location을 보내서 브라우저가 새로운 HTTP 요청을 하게 만드는 것입니다. 이 점이 RequestDispatcher.forward()와의 가장 중요한 차이입니다.
```

```aiignore
                </body>
                </html>
                """);
    }

Content-Type: text/html
Refresh: 3; url=/main

<html>
    현재 페이지 내용...
</html>
```

#### 8.3 dispatch
```aiignore
dispatch 는 클라이언트의 웹 브라우져를 거치지 않고 서버에서 포워딩이 진행된다.
따라서, 웹 브라우저 주소창의 URL 이 변경되지 않는다.
즉, 클라이언트 측에서는 포워딩이 진행되었는지 알 수 없다.
```
